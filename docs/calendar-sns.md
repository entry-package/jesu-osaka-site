# 府内イベントカレンダーとSNSの接続
2026-10-21 社長の直接依頼。実行機は豊中Mac mini、既存の週次カレンダーと日次SNS制作を使う。新しい投稿ジョブやアカウントを作らない。

カレンダー公開・公開先照合・編集元への取込が成功した後、次を実行する。
```sh
python3 /Users/yukuno/.local/share/jesu-osaka/repo/scripts/queue-calendar-sns.py --output <run>/sns-intake.json
```
データと本番events.htmlのカレンダー欄が一致した場合だけ既存mascot-editorial/inboxへ事実パックを渡す。試験用frozenデータは渡さない。週単位の題材IDと内容SHAで重複排除し、取得日更新だけでは原稿を増やさない。失敗時は記録し、サイトの正常公開を巻き戻さず、同じコマンドから再開する。

既存x-weekly-draftsがJeSU大阪のX @OsakaGamers向けにパックゼロの原稿を制作する。週の案内・今後30日の主要な見どころ・サイトへの参加導線を中心にし、個別イベントの本文を出す前は当日の公式発表を再確認する。外部イベントをJeSU主催と書かない。終了・中止を事前告知に混ぜず、未公開案件は含めない。

現行人格と成長ノート、直近の同アカウント投稿・既存承認行・配信結果を確認してから現行SNSスキルの枠取得→campaign_pipeline prepare-batch --slot-inventory→sheet-prependで既存「媒体別承認」へ未チェックの版を提出する。新しい承認先は作らない。イベント画像は公式公開済み素材だけ、確認できなければテキスト。サイトの週次自動公開許可はSNS投稿の許可ではない。社長本人の版ごとのA列チェックと受付記録を経て、既存配車係が公開・読戻し・Discord通知する。

導入時の手動の受け渡し・承認表登録と、次回の定刻での連携は別に記録する。

2026-10-21 配車基盤更新への追随: 新規X稿は現行のreferences/x-official-publication-policy.mdを優先し、両承認タブと標準予約の新しいslot-inventoryを取得してprepare-batchで枠を確定する。同一アカウント60分の間隔と原稿別の公開期限を内容SHAに結び付ける。既に承認/公開済みの初回稿は書き換えない。現在の投稿係は既存ブラウザ経路であり、無効な旧API比較案のOAuth/残高を停止理由にしない。新規OAuth・課金・新規送信経路をこの手順から追加しない。

## PACkage側へ展開しない（2026-10-22）
JeSU大阪とPACkageは別主体。カレンダー由来の地域情報はJeSU大阪 X・Webに限定し、PACkageのSNS/Web、社内Discord、PACsへ自動展開しない。JeSU大阪またはPACkage自身の主催・運営等の関与が確認できるものだけを、独立した自社告知として扱う。パコの正規経路が不調な場合も通常アカウントへ切り替えない。地域カレンダーの掲載基準・週次公開範囲は変更しない。
