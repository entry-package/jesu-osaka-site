# 大阪府内イベントカレンダー 掲載・週次更新基準 v1.2
施行: 2026-10-20 / 管理: JeSU大阪サイト担当 / 指示者: 山口 勇

## 掲載するもの
一般の府内主要イベントは次の全項目を満たすものを掲載する。PACkage関連には下記の専用基準を適用する。
1. 大阪府内に来場できる現地会場があり、開催日・会場が主催者から正式発表されている。
2. eスポーツ競技、ゲームの対戦・観戦・体験を主目的とする。競技・観戦・実際のゲームプレイ参加が中心であること。作品の展示・映像鑑賞・ライド体験が中心の催事、物販のみ、一般的な音楽公演、通常配信は対象外。
3. JeSU本部・地方支部の主催／公認行事、ゲームメーカーの公式主要大会・公式フェス、プロチーム／配信者本人または運営法人が主催する大型ゲームイベント、自治体主催・支援の主要eスポーツ大会のいずれか。
4. 「主要・大型」の根拠は、全国・国際大会の本戦／公式地方予選、メーカーの公式ゲームフェス、自治体の大規模大会支援対象、または公表定員300人以上のホール／アリーナ等でのチーム・配信者主催ゲームイベント。JeSUの公式勉強会・公認行事は規模条件を除外する。
5. 公式URLと確認日を保存できる。未公表の来場者数・人気・フォロワー数から規模を推測しない。

## PACkage関連の全件掲載（2026-10-20 社長直接指示）
大阪府内の公開済みイベントで、株式会社PACkageの主催・共催・企画運営・運営協力・出演を公式に確認できるものは、規模・ジャンルを問わず全件掲載する。PACkage関連の発表済み予定は180日より先も保持・表示する。PACFES、PACLAN、PAC CUP、OsakaPNG、PACs、実行委員会形式のゲームパビリオンjpなどを毎週確認。ゲームプレイ中心・定員300人等の一般枠の制約を適用しない。小規模交流会、勉強会、体験会、展示会、公演も対象。府外・オンライン限定・未発表は引き続き対象外。
category=package、importance.kind=package_related、package_relationにentity/role/evidence_urlを必須化する。PACkage公式の関係説明と当該イベントの公式日程を両方確認する。実行委員会主催はそのまま表記しPACkageの参画と区別。単に会場が同じ、知人、過去受託という理由で関係イベントと推測しない。
JeSU大阪の自社開催予定に同一回が既にある場合、重複カードを作らず掲載済み参照を週次台帳へ記録する。未公表案件は内部候補として残し、顧客名・日付等を公開データへ転記しない。

## 公式情報の判定
主催者・ゲーム権利者・JeSU・自治体の公式サイトを優先。公式サイトからリンクされた運営イベントサイトと公式販売ページも使える。SNSだけの場合は、そのアカウントが公式サイトからリンクされていることと該当告知の固定URLを記録する。認証マークだけで公式と判断しない。まとめサイト・ファン投稿・報道の転載は探索の手掛かりまで。独立コミュニティ大会を「公式」と呼ばない。
新規主催者ドメインは運営法人・公式サイトとの関係を確認し、content/event-policy.jsonに根拠とともに追加する。ドメイン一致だけで内容を信用しない。

## 掲載しないもの
府外、オンライン限定、会場・日程未発表、リーク・噂、通常の店舗対戦会・小規模交流会（PACkage関連・JeSU公式行事を除く）、IP許諾や主催者の公式性を確認できない大会、物販だけの催事。関西巡回は大阪の開催日だけを載せる。同一大会は大会IDと開催回・日程・会場で重複を除く。無関係な中間日を連続開催扱いしない。

## 表示
「JeSU大阪の開催予定」の直下に「府内のイベント予定」を置く。月間カレンダーと日程順リスト、種別フィルター、公式サイトへのリンク、情報確認日、掲載基準へのリンクを付ける。外部イベントの主催者を明記し、JeSU大阪の主催・公認と誤認させない。予定・変更・中止・終了を区別。時間・参加費未公表なら未公表と表示する。原則今後180日、発表済みの主要大会は追跡候補台帳へ。
画像を転用せずテキスト掲載を既定とする。公式に公開済みでも転載許諾が確認できなければコピーしない。

## 毎週月曜日09:00（日本時間）
実行機は豊中Mac mini。既存cli-automation.pyからCodex CLIを起動。
1. 最新の公式発表を検索し、既存掲載URL・メーカー・JeSU・主要チーム／配信者の公式サイトを確認。
2. 既存全件の日程・会場・申込先・中止／延期を再確認。取得不能は0件・開催中止と扱わない。情報確認日を成功分だけ更新し、8日超は要再確認表示。
3. 採用／見送り／取得不能の理由・公式URL・確認日時を週次記録へ保存。新規候補は上の判定をすべて行う。
4. 専用Git worktreeと週次ブランチでJSONを更新し、render-events.py、ビルド、検証、行動テストを実行。作業中の元ブランチを上書きしない。
5. 終了済みは今後の予定から除外し、記録は台帳に保持。中止は日程を消さず中止を明示。延期で新日程未定は予定枠から外す。
6. 会社共有Driveの既存確認フォルダへ確認版・差分・根拠を保存し、クラウド再取得で照合。Notionの同じ作業ログへ確認待ち記録を追記。
7. 社長に提示した版への明確なOKが出た後、既存テスト公開→本番確認の手順へ。週次ジョブはpush・本番公開・SNS投稿・社外送信を行わない。

失敗時は最後の正常データを維持し、失敗と未確認を記録。空一覧で置き換えない。更新日を偽って進めない。戻すときは当該ジョブをpauseし、保存済み定義と直前Gitコミットへ戻す。削除・強制pushは使わない。

表示上の追記: PACkageの役割行と概要での参画説明は省略する。正式主催者とPACkage関連カテゴリを表示し、関係根拠は内部データのみで管理する（社長直接指示）。

表示補足: カレンダーは当月から開き、初期の一覧は全月の今後の予定を日程順に表示。月別ボタンから選ぶと当該月に絞る。自社開催はカレンダーにも掲載し、上部の同じ開催案内へリンクする。
